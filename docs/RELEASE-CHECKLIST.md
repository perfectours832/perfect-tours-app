# בדיקות לפני פרסום

המסמך הוא רשימת בדיקות לשחרור, ולא אישור שהבדיקות בוצעו. יש לתעד בנפרד תוצאות בדיקות אוטומטיות ומקומיות שבוצעו בפועל. בדיקות מול Supabase מחייבות סביבת בדיקה או רשומות וחשבונות בדיקה מפורשים; אין לשנות נתוני לקוחות אמיתיים.

אין לפרסם את האתר, למזג לענף הראשי או להפעיל SQL ללא אישור הפרסום המתאים. הבדיקה וה־Pull Request אינם פריסה.

## סביבת בדיקה ונתונים

- [ ] לאמת שהגרסה הנבדקת היא ענף הפיתוח וה־commit המיועדים ל־Pull Request.
- [ ] להשתמש ב־Supabase נפרד לבדיקות, או בחשבונות ורשומות בדיקה שאושרו במפורש. לא להריץ את הבדיקות האוטומטיות מול נתוני ייצור.
- [ ] לבדוק את הטיפוס האמיתי של `trips.itinerary` ושל `documents`, ברירות מחדל של בעלות והגבלות העמודות. JSONB הוסק מהקוד ולא אומת.
- [ ] להחזיק גיבוי ויכולת חזרה לגרסה קודמת לפני פריסה; לא להריץ מיגרציה במסגרת הגרסה הבסיסית.
- [ ] לוודא שאין בקוד האתר `service_role`, מפתח סודי או פרטי חשבון. מפתח Supabase ציבורי אינו תחליף ל־RLS.

## התחברות וכניסות ישנות

- [ ] להתחבר בחשבון סוכן לבדיקה, לרענן, לוודא שההתחברות נשמרת ולהתנתק.
- [ ] לבדוק סיסמה שגויה ושגיאת רשת, ולוודא שמופיעה הודעה שימושית ללא הבטחה לשמירה או התחברות שלא בוצעו.
- [ ] לבדוק את `password.html`: קישור איפוס בחשבון בדיקה, תפוגת קישור, אימות סיסמאות, שינוי מוצלח וכניסה מחדש. לוודא שכתובת החזרה מורשית ב־Supabase.
- [ ] לבדוק כניסה דרך `admin.html`, `client.html` ו־`index-new.html`, כולל קישור לקוח קיים עם פרמטר מסלול. לוודא שההפניה מובילה לכניסה הקנונית ושומרת על מזהה החופשה.
- [ ] לבדוק קישור מסלול לא תקין או חסר ולוודא שאין מידע של חופשה אחרת.

## שמירה, טעינה ותאימות

- [ ] ליצור חופשת בדיקה עם שני ימים, כמה פעילויות ויום ריק. לשמור, לרענן ולטעון שוב.
- [ ] לערוך פעילות, לשנות סדר פעילויות וימים, למחוק פעילות בבדיקת נתונים מפורשת ולוודא שכל השינויים נטענים מחדש.
- [ ] לבדוק תיאורים רב־שורתיים, תווי `|`, עברית, כתובות ארוכות, משך, תמונה, מסמך ומפות.
- [ ] לבדוק שכרטיס שנרכש, שעה מומלצת, שעת כניסה מחייבת וסטטוס הזמנה נשמרים ומוצגים בנפרד.
- [ ] לטעון מסלול ישן מובנה ולוודא תאימות. לבדוק ששינוי בפרטי החופשה בלבד משמר את ערך המסלול המקורי ושדות לא מוכרים.
- [ ] לטעון טקסט חופשי ישן ולוודא שלא מתבצעת המרה או כתיבה בעת פתיחה. לבדוק ביטול ייבוא, סקירת תצוגה מקדימה ואישור מפורש לפני שמירה.
- [ ] לדמות שגיאת שמירה או ניתוק רשת ולוודא שאין הודעת הצלחה ושהטיוטה נשארת זמינה לתיקון.
- [ ] לוודא שלא נוסף עדכון אוטומטי של מסלול קיים בעת ביקור לקוח או מעבר שפה.

## הרשאות בצד השרת — נדרש אימות נפרד

בדיקות אלה לא הושלמו מקריאת קוד האתר. נדרשים בדיקת סכמת Supabase, מדיניות RLS, הגדרות RPC וחשבונות בדיקה.

- [ ] משתמש אנונימי אינו יכול לקרוא את טבלת החופשות או ההגדרות ישירות ואינו יכול ליצור, לשנות או למחוק חופשה.
- [ ] סוכן בדיקה א׳ אינו יכול לקרוא או לשנות חופשה או מסמך של סוכן בדיקה ב׳, גם באמצעות קריאת API ישירה.
- [ ] הבעלות על חופשה חדשה נקבעת ונאכפת בשרת. אי אפשר לבחור בעלים אחר באמצעות שינוי בקשת הדפדפן.
- [ ] `get_public_trip` מחזיר רק את החופשה של הקישור המדויק, רק את השדות הנחוצים ללקוח, ומסרב לקישור לא תקין או לא מורשה.
- [ ] מדיניות טיוטות מפורשת ונבדקת: מסלול בסטטוס `draft` אינו נחשף ללקוח אם הוגדר כלא מפורסם. אין להסתמך על הסתרת קישור בממשק.
- [ ] `get_public_settings` אינו חושף הגדרות פרטיות. לפני ריבוי סוכנויות הוא חייב להיות מוגבל להקשר הסוכנות של המסלול.
- [ ] הרשאות פונקציות RPC ו־`security definer`, אם קיים, נבדקו כולל `search_path`, הרשאות execute והגבלת נתונים.
- [ ] מסמכי לקוחות אינם בבאקט ציבורי בלתי מוגבל. קישור חתום, אם קיים, פג בזמן שנקבע ואינו מעניק גישה למסמכים אחרים.
- [ ] סינון URL, הגנות חלון חדש ומדיניות referrer פעילים; קישורי `javascript:` ו־`data:` אינם פעילים כקישורי מפות או מסמכים.

## ממשק לקוח בטלפון אנדרואיד

- [ ] לבדוק ב־Chrome לאנדרואיד, ובאמולציה של רוחבים 360, 393 ו־412 פיקסלים לפחות. אמולציה אינה מחליפה בדיקה במכשיר אמיתי.
- [ ] לבדוק עברית ו־RTL: סדר אייקונים, שעות ומספרים, טקסט ארוך, חיצים, גלילה ופתיחת כרטיסיות. לבדוק גם מעבר ל־English וחזרה.
- [ ] לוודא שאין גלילה אופקית, כותרות חותכות או כפתורים מחוץ למסך, כולל בהגדלת גופן.
- [ ] בתצוגה הסגורה מופיעים רק זמן, שם וסימון כרטיס רלוונטי; פרטי פעילות וקישורים נגישים בכרטיסייה הפתוחה.
- [ ] לבדוק ניווט מקלדת, סימון מיקוד, שמות נגישים, ניגודיות וגודל אזורי לחיצה.
- [ ] לבדוק תמונה חסרה, קישור לא תקין, מסלול ריק, מסלול ישן, יום ריק ומסלול עם הרבה פעילויות.
- [ ] לבדוק מפות ומסמכים ממכשיר הבדיקה, בלי לשלוח הודעות או לשנות הזמנות אצל ספקים.
- [ ] לוודא ש־manifest ואייקונים נטענים אם מופיעה אפשרות התקנה. אין להבטיח פעולה ללא אינטרנט ללא בדיקה ומימוש ייעודיים.
- [ ] לצרף ל־Pull Request צילומי מסך של לקוח בעברית במסך טלפון ושל העורך, עם סימון נתוני בדיקה.

## יכולות שטרם פעילות

בקשות שינוי עם טיפול בדשבורד, דיווחי פעילות, דירוגים, דוחות יומיים, תזכורות, Push, SMS, Passkeys, סליקה, מנויים, ריבוי סוכנויות ופרסום בחנויות אינם חלק מהגרסה הבסיסית. אין להציג שמירה, שליחה, דירוג או ביטול הזמנה כהצלחה ללא מימוש מאומת. קישור יצירת קשר, אם מופיע, אינו מערכת בקשות שינוי.

עדכון שלב ד׳: דיווחי פעילות, דירוגי פעילות/יום/חופשה/שירות, סיכומי יום, דוח סוכן ובקשות שינוי עם מענה נוספו לענף הפיתוח ונבדקו. הפעלתם דורשת את המיגרציה ב־[FEEDBACK-SETUP.md](FEEDBACK-SETUP.md). תזכורות ושליחה אוטומטית, Push, SMS, Passkeys והיכולות המסחריות עדיין לא מומשו.

- [ ] להשלים את בדיקות השרת והטלפון הרלוונטיות ולתעד את תוצאותיהן.
- [ ] לקבל אישור מפורש לפני מיזוג או פריסה לאתר הקיים.
